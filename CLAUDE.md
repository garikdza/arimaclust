# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Consistent model-based clustering of ARIMA time series. Each series gets an auto-fitted ARMA model, the models are compared through their AR(∞) representations (the Piccolo distance by default, or the LPC cepstral or Maharaj Mahalanobis distance), and the series are clustered on the resulting distance matrix. The theory (assumptions and the consistency result) is in the paper cited in the README.

## Commands

The project is managed with uv (`pyproject.toml`, hatchling backend).

- `uv sync`: install the library plus the dev tools (pytest, pytest-cov, ruff).
- `uv run pytest`: run the tests, including sklearn's estimator checks (`tests/test_sklearn_checks.py`), but not the tests marked `slow`. For a single test use `uv run pytest tests/test_metrics.py::test_mahalanobis_tau1_hand_value`.
- `uv run pytest -m slow`: run the slow statistical tests (clustering recovery rising with series length). Add a node id after `-m slow` to run one; without `-m slow`, a slow test is deselected even when named by node id.
- `uv run pytest --cov`: run the tests with a coverage report for `arimaclust`. It fails below the 85% floor set in `pyproject.toml`, the same check CI runs. Add `--cov-report=html` for a browsable report.
- `uv run ruff check .`: lint (rules E, F, I, UP and B, line length 120, notebooks excluded). `src = [".", "examples"]` makes `synthetic`, `results` and `style` first-party imports.
- `uv run ruff format .`: format the code (single quotes; Markdown is excluded so README code blocks keep their aligned comments). CI runs `ruff format --check .` and fails on unformatted code.
- `uv sync --extra examples`: also install matplotlib, which only the example scripts need.
- `uv run --extra examples python examples/<script>.py`: run one example script. They need no network and no GPU, and write their figures to `examples/figures/`; only the three figures the README shows (`accuracy_vs_length.png`, `estimated_distance.png` and `accuracy_vs_delta.png`) are tracked, and `.gitignore` keeps the rest out. The four scripts that fit models save their raw results as `examples/figures/<script>.npz` and redraw from that file on later runs; add `--recompute` to fit again, as needed after changing a script's settings or a curated set (a changed setting is not detected).
- CI (`.github/workflows/ci.yml`) runs ruff and the default tests with coverage on pushes to `main` and on PRs, and uploads the report to Codecov.
- Nothing here needs a GPU. Prefix Python runs with `CUDA_VISIBLE_DEVICES=""`, as the global GPU rule requires.

## Tests

Tests are unit tests that mirror the code layout: one test file per module, at the mirrored path, named `test_<module>.py`, for example `examples/synthetic.py` → `tests/examples/test_synthetic.py`.

- `arimaclust`'s tests sit directly in `tests/`, one file per area: `test_modeling.py` for `modeling.py`, `test_metrics.py` for the metric functions, `test_distance.py` for `ARMADistance`, `test_clustering.py` for `clustering/`, `test_data.py` for `data/`, and `test_sklearn_checks.py` for sklearn's estimator checks.
- The `examples/` figure scripts are entry points and are run by hand. The modules they import, `synthetic.py`, `results.py` and `style.py`, are unit-tested.
- pytest's `pythonpath = ["examples"]` lets the tests `import synthetic`, `import results` and `import style`, as the scripts do. None of these modules may import matplotlib, so their tests run under a plain `uv sync`, as in CI.

## Architecture

The pipeline is `fit a model per series → distance matrix → cluster`, one part per stage: `modeling.py`, `metrics/`, `clustering/`, plus `data/` for synthetic data. The public API is the three estimators exported from `arimaclust/__init__.py`, the two generators exported from `arimaclust.data`, and `modeling.ARIMA`, the type of `ARMADistance.models_`; everything else is internal.

- `modeling.py`: `ARIMA(ar, ma, d=0, series=None)`, a frozen dataclass and the one model type every stage passes around: an ARIMA(p, d, q) model φ(B)(1−B)^d x_t = θ(B)e_t, optionally with the undifferenced series it was fitted to. `ARIMA.fit(x, **kwargs)` is the constructor that selects and fits one with `pmdarima.auto_arima` (kwargs override the fixed options); orders are selected by **BIC by default**, which the consistency theory requires (AIC is not consistent), with pmdarima's stepwise search rather than the full search the theorem assumes. `order` gives `(p, d, q)`, `ar_polynomial` the coefficients of φ(B)(1−B)^d, `arma_process` the ARMA part as a statsmodels `ArmaProcess`, `pi(tau)` the AR(∞) coefficients π₁…π_tau of φ(B)(1−B)^d / θ(B) (raises unless invertible), and `differenced()` the ARMA(p, q) model with the series differenced `d` times.
- `metrics/autoregressive.py`: distances between two `ARIMA`s, all on their AR(∞) coefficients, so the differencing is part of what they compare. `tau` defaults to 50 everywhere and is checked by `utils.check_tau` (an integer ≥ 1).
  - `piccolo` compares π₁…π_tau, and `cepstral` the first `tau` LPC cepstral coefficients.
  - `mahalanobis` is Maharaj's Wald statistic on the π-weights of each model's `differenced()` ARMA part, weighted by that series' autocovariances and length. It needs the models' series, each longer than `tau` after differencing.
  - `METRICS` maps each name `ARMADistance` accepts to its function, so a new metric goes there.
- `metrics/matrix.py`: `dist_matrix_parallel(items, metric, n_jobs)` computes the pairs with joblib (`None` runs serially). A dict input gives a DataFrame labelled by its keys, a list an ndarray.
- `metrics/distance.py`: `ARMADistance(max_p=3, max_q=3, d=0, metric='piccolo', tau=50, arima_kwargs=None, n_jobs=None)`, an sklearn transformer with `fit` and `fit_transform` only (new series can't be compared without refitting the collection). It reads a list of 1-D series (lengths may differ), a 2D array (one series per row) or a DataFrame (one series per column, NaNs dropped), and validates the parameters and every series before fitting any of them. It then fits one `ARIMA` per series in parallel (a failed fit is re-raised naming the series), checks that each is invertible (the error names the series), and fills `models_` and `dist_matrix_` (a list and an ndarray; for a DataFrame, a `{column: model}` dict and a DataFrame labelled by the columns).
  - `arima_kwargs` override the fit defaults but must not set `max_p`, `max_q` or `d`. `start_p` / `start_q` are clamped to the maximum orders. `d=None` lets auto_arima pick `d` per series; `'mahalanobis'` needs an integer `d`. `n_jobs` covers both the fits and the distance matrix.
- `clustering/`: sklearn clusterers taking `distance=None | ARMADistance(...) | 'precomputed'`. `_input.py`'s `DistanceInputMixin` fits a clone of `distance` (`None` means `ARMADistance()`) into `distance_`, or validates `X` as a square matrix for `'precomputed'` and sets the `pairwise` sklearn tag. The `distance` parameter itself is never fitted. Both clusterers fill `labels_` and provide `fit_predict`, but no `predict`.
  - `consistent.ConsistentClustering(n_clusters=2)` starts farthest-point selection at sample 0, then assigns each sample to its nearest centre (`centers_` holds the centre sample indices). When the farthest remaining sample is at distance 0, that is when there are fewer distinct groups than `n_clusters`, it warns (`UserWarning`) and stops with the centres found, so `centers_` can be shorter than `n_clusters`. This is the algorithm with the consistency proof.
  - `threshold.ThresholdClustering(alpha)` builds the graph of pairs with distance ≤ `alpha` and returns its connected components as clusters. `alpha` has no default and must be a number ≥ 0.
- `data/`: the public synthetic data generators, `generate_arma_sample(ar_params, ma_params, length, burnin=100, random_state=None)` and `generate_clusters(params, length, n_per_cluster, random_state=None)` (returns the series grouped by cluster and the labels as an ndarray). Each process is an `(ar_params, ma_params)` tuple. `random_state` is an int, a `np.random.Generator` or `None`, so nothing uses numpy's global random state. A burn-in of 100 draws is discarded so each series starts near the stationary distribution. Parameter sets live in `examples/synthetic.py`, not in the package.

`examples/` (not in the wheel, no `__init__.py`) holds synthetic examples at a controlled separation δ, the smallest Piccolo distance (`tau=50`) between the processes that generate the clusters.

- `synthetic.py`: `BANDS` (four δ bands) and `band_of`, `CURATED_SETS` (one three-cluster `CuratedSet` per band, its δ recorded and checked in the tests), `min_separation`, `EXAMPLE1` / `EXAMPLE2` (a far and a near pair of processes, used by `tests/test_metrics.py` and `tests/test_data.py`), `generate_separated_params(n_clusters, delta, seed)` (random stationary, invertible ARMA(≤2, ≤2) processes kept greedily while pairwise ≥ δ; raises `RuntimeError` after `max_draws`) and `clustering_scores` (one seeded draw, `ConsistentClustering` + default `ARMADistance` fit and AMI per seed). No matplotlib.
- `results.py`: `save_results` / `load_results` (a dict of arrays as a `.npz` file, no pickle, so object arrays are rejected at save), `load_or_compute(path, compute, recompute)` (computes and saves when the file is missing or `recompute` is set, then always returns what it reads back from the file) and `parse_args`, the `--recompute` flag. No matplotlib.
- `style.py`: the minimal figure style every script draws in, `MINIMAL` (matplotlib rc settings for `plt.rc_context`), and the colours: `BAND_COLOURS` (one blue per δ band, darker for larger δ), `CLUSTER_COLOURS` and `DISTANCE_RAMP`. No matplotlib.
- The scripts, each writing to `examples/figures/` in the `style.MINIMAL` style: `accuracy_vs_length.py` (AMI against length per band, the README's top figure), `accuracy_vs_delta.py` (AMI against δ on generated two-cluster sets, a README figure), `distance_matrix.py` (`distance_matrix.png`: heatmap and MDS embedding of a fitted distance matrix, misclustered series circled), `distance_estimation.py` (fitted against true δ by length, a README figure) and `processes.py` (sample series and true AR(∞) coefficients). They import `synthetic`, `results` and `style` as sibling modules. The four that fit models (all but `processes.py`) have a `compute()` that fits and returns the raw arrays (every draw's AMI or every distance estimate, the full distance matrix, plus the labels, lengths and δs the plot needs), a `plot(results)` that draws only from those loaded arrays, and a `main()` that joins them through `results.load_or_compute`, saving to `figures/<script>.npz`. `processes.py` fits nothing and draws directly.
