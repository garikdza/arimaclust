# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Consistent model-based clustering of ARIMA time series. Each series gets an auto-fitted ARMA model, the models are compared through their AR(∞) representations (the Piccolo distance by default, or the LPC cepstral or Maharaj Mahalanobis distance), and the series are clustered on the resulting distance matrix. The theory (assumptions and the consistency result) is in the paper cited in the README.

## Commands

The project is managed with uv (`pyproject.toml`, hatchling backend).

- `uv sync`: install the library plus the dev tools (pytest, pytest-cov, ruff).
- `uv run pytest`: run the tests, including sklearn's estimator checks (`tests/test_sklearn_checks.py`), but not the tests marked `slow`. For a single test use `uv run pytest tests/metrics/test_autoregressive.py::test_mahalanobis_tau1_hand_value`, and for one area its folder, as in `uv run pytest tests/clustering`.
- `uv run pytest -m slow`: run the slow statistical tests (clustering recovery rising with series length). Add a node id after `-m slow` to run one; without `-m slow`, a slow test is deselected even when named by node id.
- `uv run pytest --cov`: run the tests with a coverage report for `arimaclust`. It fails below the 85% floor set in `pyproject.toml`, the same check CI runs. Add `--cov-report=html` for a browsable report.
- `uv run ruff check .`: lint (rules E, F, I, UP and B, line length 120, notebooks excluded). `src = [".", "examples", "examples/synthetic", "examples/fred_md"]` makes `results`, `style`, `synthetic` and `fred_md` first-party imports.
- `uv run ruff format .`: format the code (single quotes; Markdown is excluded so README code blocks keep their aligned comments). CI runs `ruff format --check .` and fails on unformatted code.
- `uv sync --extra examples`: also install matplotlib, which only the example scripts need.
- `uv run --extra examples python examples/<folder>/<script>.py`: run one example script, for example `examples/synthetic/accuracy_vs_length.py` or `examples/fred_md/clusters.py`. None needs a GPU. The synthetic scripts need no network; `examples/fred_md/clusters.py` downloads the FRED-MD vintage on its first run, so it needs the network then, and caches it in `examples/fred_md/data/`, which `.gitignore` keeps out. Each script writes its figures to its own folder's `figures/`. Only the five figures the READMEs show are tracked (`examples/synthetic/figures/` `accuracy_vs_length.png`, `estimated_distance.png` and `accuracy_vs_delta.png`; `examples/fred_md/figures/` `autocorrelation_profiles.png` and `distance_matrix.png`), and `.gitignore` keeps the rest out. The scripts that fit models save their raw results as `figures/<script>.npz` in their folder and redraw from that file on later runs; add `--recompute` to fit again, as needed after changing a script's settings or a curated set (a changed setting is not detected).
- CI (`.github/workflows/ci.yml`) runs ruff and the default tests with coverage on pushes to `main` and on PRs, and uploads the report to Codecov.
- Nothing here needs a GPU. Prefix Python runs with `CUDA_VISIBLE_DEVICES=""`, as the global GPU rule requires.

## Tests

Tests are unit tests of `arimaclust`, and `tests/` mirrors the package: `arimaclust/<path>/<module>.py` is tested in `tests/<path>/test_<module>.py`. `test_sklearn_checks.py` (sklearn's estimator checks) is the one file spanning modules, and re-exporting `__init__.py` files get no test file.

- A test sits in the file of the module that holds the code it exercises, and errors are tested where they are raised: `n_clusters` checks in `test_consistent.py` / `test_kmedoids.py`, the `distance` and square-matrix checks in `test_input.py`, `tau` validation in `test_utils.py` (each caller keeps one test that it validates).
- Test folders have no `__init__.py`: pytest runs with `--import-mode=importlib` (`addopts` in `pyproject.toml`), so test files can't import each other. Helpers shared across files are fixtures in `tests/conftest.py`; a helper or constant used by one file stays in that file.
- Names say the behaviour checked, `test_<what>_<expected outcome>`, such as `test_kmedoids_swap_tie_lowest_outgoing_index`. Expected values come from hand calculation or a closed form, explained in a comment, not from rerunning the code under test. Bad inputs go through one parametrized test per module, each case with an `id`, matching the error message.
- Every test checks behaviour: no tests that only pin a default or a `get_params()` dict, only check an output's shape, or repeat a check made elsewhere.
- Coverage measures `arimaclust` only.
- The `examples/` code has no tests: the scripts are run by hand.
- pytest's `pythonpath = ["examples/synthetic"]` lets `tests/metrics/test_autoregressive.py`, `tests/metrics/test_matrix.py` and `tests/data/test_generate.py` `import synthetic` for its `EXAMPLE1` / `EXAMPLE2` parameter sets, so `synthetic.py` must not import matplotlib: the tests run under a plain `uv sync`, as in CI. The other modules the scripts share (`results.py`, `style.py`, `fred_md.py`) keep matplotlib out too, leaving it to the scripts.

## Architecture

The pipeline is `fit a model per series → distance matrix → cluster`, one part per stage: `modeling.py`, `metrics/`, `clustering/`, plus `data/` for synthetic data. The public API is the four estimators exported from `arimaclust/__init__.py`, the two generators exported from `arimaclust.data`, and `modeling.ARIMA`, the type of `ARMADistance.models_`; everything else is internal.

- `modeling.py`: `ARIMA(ar, ma, d=0, series=None)`, a frozen dataclass and the one model type every stage passes around: an ARIMA(p, d, q) model φ(B)(1−B)^d x_t = θ(B)e_t, optionally with the undifferenced series it was fitted to. `ARIMA.fit(x, **kwargs)` is the constructor that selects and fits one with `pmdarima.auto_arima` (kwargs override the fixed options); orders are selected by **BIC by default**, which the consistency theory requires (AIC is not consistent), with pmdarima's stepwise search rather than the full search the theorem assumes. `order` gives `(p, d, q)`, `ar_polynomial` the coefficients of φ(B)(1−B)^d, `arma_process` the ARMA part as a statsmodels `ArmaProcess`, `pi(tau)` the AR(∞) coefficients π₁…π_tau of φ(B)(1−B)^d / θ(B) (raises unless invertible), and `differenced()` the ARMA(p, q) model with the series differenced `d` times.
- `metrics/autoregressive.py`: distances between two `ARIMA`s, all on their AR(∞) coefficients, so the differencing is part of what they compare. `tau` defaults to 50 everywhere and is checked by `utils.check_tau` (an integer ≥ 1).
  - `piccolo` compares π₁…π_tau, and `cepstral` the first `tau` LPC cepstral coefficients.
  - `mahalanobis` is Maharaj's Wald statistic on the π-weights of each model's `differenced()` ARMA part, weighted by that series' autocovariances and length. It needs the models' series, each longer than `tau` after differencing.
  - `METRICS` maps each name `ARMADistance` accepts to its function, so a new metric goes there.
- `metrics/matrix.py`: `dist_matrix_parallel(items, metric, n_jobs)` computes the pairs with joblib (`None` runs serially). A dict input gives a DataFrame labelled by its keys, a list an ndarray.
- `metrics/distance.py`: `ARMADistance(max_p=3, max_q=3, d=0, metric='piccolo', tau=50, arima_kwargs=None, n_jobs=None)`, an sklearn transformer with `fit` and `fit_transform` only (new series can't be compared without refitting the collection). It reads a list of 1-D series (lengths may differ), a 2D array (one series per row) or a DataFrame (one series per column, NaNs dropped), and validates the parameters and every series before fitting any of them. It then fits one `ARIMA` per series in parallel (a failed fit is re-raised naming the series), checks that each is invertible (the error names the series), and fills `models_` and `dist_matrix_` (a list and an ndarray; for a DataFrame, a `{column: model}` dict and a DataFrame labelled by the columns).
  - `arima_kwargs` override the fit defaults but must not set `max_p`, `max_q` or `d`. `start_p` / `start_q` are clamped to the maximum orders. `d=None` lets auto_arima pick `d` per series; `'mahalanobis'` needs an integer `d`. `n_jobs` covers both the fits and the distance matrix.
- `clustering/`: sklearn clusterers taking `distance=None | ARMADistance(...) | 'precomputed'`. `_input.py`'s `DistanceInputMixin` fits a clone of `distance` (`None` means `ARMADistance()`) into `distance_`, or validates `X` as a square matrix for `'precomputed'` and sets the `pairwise` sklearn tag. The `distance` parameter itself is never fitted. All three clusterers fill `labels_` and provide `fit_predict`, but no `predict`.
  - `consistent.ConsistentClustering(n_clusters=2)` starts farthest-point selection at sample 0, then assigns each sample to its nearest centre (`centers_` holds the centre sample indices). When the farthest remaining sample is at distance 0, that is when there are fewer distinct groups than `n_clusters`, it warns (`UserWarning`) and stops with the centres found, so `centers_` can be shorter than `n_clusters`. This is the algorithm with the consistency proof.
  - `kmedoids.KMedoids(n_clusters=2, init='build', max_iter=300)` is PAM k-medoids. It starts from PAM BUILD (`init='build'`: the sample with the lowest total distance, then the one lowering the total distance most) or from farthest-point selection (`init='farthest'`: exactly `ConsistentClustering`'s centres), then runs best-improvement swap iterations, each making the exchange of a medoid for a non-medoid that lowers the total distance most, until none does. `medoids_` holds the medoid sample indices in selection order (a swap replaces a medoid in place), `labels_` each sample's position in `medoids_`, `inertia_` the total distance to the medoids and `n_iter_` the swap iterations run (the last one, finding no improving swap, included; `max_iter` when capped). Ties go to the lowest sample index in the start and in the swaps (the incoming sample first, then the outgoing medoid); a sample at equal distance from two medoids goes to the one listed first in `medoids_`. It warns (`UserWarning`) and keeps fewer medoids when there are fewer distinct groups than `n_clusters`, as `ConsistentClustering` does, for either start, and warns (`ConvergenceWarning`) when `max_iter` iterations leave an improving swap. It has no consistency guarantee.
  - `threshold.ThresholdClustering(alpha)` builds the graph of pairs with distance ≤ `alpha` and returns its connected components as clusters. `alpha` has no default and must be a number ≥ 0.
- `data/`: the public synthetic data generators, `generate_arma_sample(ar_params, ma_params, length, burnin=100, random_state=None)` and `generate_clusters(params, length, n_per_cluster, random_state=None)` (returns the series grouped by cluster and the labels as an ndarray). Each process is an `(ar_params, ma_params)` tuple. `random_state` is an int, a `np.random.Generator` or `None`, so nothing uses numpy's global random state. A burn-in of 100 draws is discarded so each series starts near the stationary distribution. Parameter sets live in `examples/synthetic/synthetic.py`, not in the package.

`examples/` (not in the wheel, no `__init__.py` anywhere) holds two example folders, each with its scripts, its `README.md` and its `figures/`, and the two modules every script shares, `results.py` and `style.py`. A script reaches the shared modules through one line before its local imports, `sys.path.insert(0, str(Path(__file__).resolve().parents[1]))`, and imports its own folder's module as a sibling.

- `results.py`: `save_results` / `load_results` (a dict of arrays as a `.npz` file, no pickle, so object arrays are rejected at save), `load_or_compute(path, compute, recompute)` (computes and saves when the file is missing or `recompute` is set, then always returns what it reads back from the file) and `parse_args`, the `--recompute` flag. No matplotlib.
- `style.py`: the minimal figure style every script draws in, `MINIMAL` (matplotlib rc settings for `plt.rc_context`), and the colours: `BAND_COLOURS` (one blue per δ band, darker for larger δ), `CLUSTER_COLOURS` (four hues; a script with fewer clusters zips with a slice of them) and `DISTANCE_RAMP`. No matplotlib.

`examples/synthetic/` holds synthetic examples at a controlled separation δ, the smallest Piccolo distance (`tau=50`) between the processes that generate the clusters.

- `synthetic.py`: `BANDS` (four δ bands) and `band_of`, `CURATED_SETS` (one three-cluster `CuratedSet` per band, its δ recorded), `min_separation`, `EXAMPLE1` / `EXAMPLE2` (a far and a near pair of processes, used by the tests in `tests/metrics/` and `tests/data/`), `generate_separated_params(n_clusters, delta, seed)` (random stationary, invertible ARMA(≤2, ≤2) processes kept greedily while pairwise ≥ δ; raises `RuntimeError` after `max_draws`) and `clustering_scores` (one seeded draw, `ConsistentClustering` + default `ARMADistance` fit and AMI per seed). No matplotlib.
- The scripts, each writing to `examples/synthetic/figures/` in the `style.MINIMAL` style: `accuracy_vs_length.py` (AMI against length per band, the README's top figure), `accuracy_vs_delta.py` (AMI against δ on generated two-cluster sets, shown in `examples/synthetic/README.md`), `distance_matrix.py` (`distance_matrix.png`: heatmap and MDS embedding of a fitted distance matrix, misclustered series circled), `distance_estimation.py` (fitted against true δ by length, shown in `examples/synthetic/README.md`) and `processes.py` (sample series and true AR(∞) coefficients). They import `synthetic` as a sibling module and `results` and `style` through the bootstrap line. The four that fit models (all but `processes.py`) have a `compute()` that fits and returns the raw arrays (every draw's AMI or every distance estimate, the full distance matrix, plus the labels, lengths and δs the plot needs), a `plot(results)` that draws only from those loaded arrays, and a `main()` that joins them through `results.load_or_compute`, saving to `figures/<script>.npz`. `processes.py` fits nothing and draws directly.

`examples/fred_md/` clusters 121 monthly US macroeconomic series from McCracken and Ng's FRED-MD (vintage 2026-01, window 1960-01..2019-12) with the cepstral `ARMADistance` and `KMedoids(n_clusters=4)`. Its `README.md` describes the data, the settings, the clusters and their caveats, quoting the script's output.

- `fred_md.py`: `fetch_vintage(path, url=VINTAGE_URL)` (downloads once and skips a cached file; writes a `.part` file and swaps it in; raises `RuntimeError` naming the URL when the download fails or returns something other than a vintage, such as the HTML page a moved file is answered with, leaving no file), `read_vintage(path)` (the levels as a DataFrame indexed by month and the transformation codes from the `Transform:` row; raises `ValueError` saying to delete the file when it is not a vintage, for example an HTML page), `transform(x, tcode)` (FRED-MD's codes 1–7, any other raises), `prepare(data, tcodes, start=START, end=END)` (transforms every series before cutting the window, then drops the series with a gap in it, keeping the file's order) and `GROUP_NAMES` / `GROUP_SERIES` / `group_ids(names)` (the eight FRED-MD groups, hard-coded from the appendix because its address carries a hash; an unknown name raises). No matplotlib.
- `clusters.py`: the script, in the same `compute()` / `plot(results)` / `main()` shape as the synthetic ones. `compute()` downloads the vintage into the gitignored `examples/fred_md/data/` unless it is cached, fits, and returns the distance matrix, labels, medoids, the members' sample autocorrelations at lags 1–12, the names, transformation codes and groups. `plot()` prints the AMI against the groups, the silhouette and each cluster's composition, autocorrelations and members, and draws `autocorrelation_profiles.png` (one panel per cluster, the median and interquartile band) and `distance_matrix.png` (heatmap ordered by cluster beside the MDS embedding, medoids circled, the main README's FRED-MD figure). The results are saved to `figures/clusters.npz`.
